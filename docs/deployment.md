# Deployment

Three supported paths, all configured by environment variables only (no code change between them):

| path | use | command |
|---|---|---|
| Docker Compose | laptop / demo / CI e2e | `cp .env.example .env && docker compose up --build` |
| Embedded dev mode | no Docker (tests, quick UI work) | `make local-db` + `make local-up` |
| Kubernetes (+ Terraform on AWS) | staging/production | below |

## 1. Docker Compose
`docker compose up --build` starts: Kafka (KRaft), Redis, MongoDB, MinIO (S3), PostgreSQL+pgvector, Mosquitto, a one-shot **`init`**
job (migrations → roles → seed 100,000 vehicles → train/score), then `api`, `ingestion-edge`, `validator`, `stream-processor`,
`lifecycle`, `simulator` (profile `sim`), `frontend`, plus Prometheus, Grafana, Jaeger, Loki and Promtail. Every container has a
health check; services wait on `service_healthy` / `service_completed_successfully`.

* UI http://localhost:8080 · API docs http://localhost:8000/docs · Grafana http://localhost:3000 (admin / `GRAFANA_ADMIN_PASSWORD`) ·
  Prometheus :9090 · Jaeger :16686 · MinIO console :9001
* First start seeds 100,000 vehicles (several minutes on a laptop). For a 30-second start set `SEED_VEHICLES=5000` in `.env`.
* Scale consumers: `docker compose up -d --scale stream-processor=3 --scale validator=2` (≤ `TOPIC_PARTITIONS`, 12 by default).
* Simulator modes: `SIM_MODE=demo|small|load|100k` (`make simulate`); scenarios: `make scenario S=engine_failure`.

> The compose stack was authored and statically validated (YAML schema, service graph, health-check wiring) but could not be run on
> the development machine (no Docker). CI (`.github/workflows/ci.yml`, job `e2e`) runs it end to end with `scripts/e2e.py`.

## 2. Kubernetes
Kustomize manifests in `infrastructure/kubernetes` (generated by `scripts/gen_k8s.py`):

* `base/`: Deployments (api ×3, ingestion-edge ×3, validator ×3, stream-processor ×6, lifecycle ×1, frontend ×2), Services, ConfigMap, Secret
  placeholder, ServiceAccount, init Job (ArgoCD PreSync hook), Ingress (TLS), HPAs, PodDisruptionBudgets, default-deny NetworkPolicies.
  Every pod: non-root, read-only root filesystem, dropped capabilities, seccomp, requests/limits, startup/liveness/readiness probes,
  topology spread across zones, Prometheus scrape annotations.
* `overlays/dev/`: single replicas + in-cluster Postgres/Redis/Mongo/Kafka for kind/minikube.
* `overlays/aws/`: ECR images, managed endpoints, IRSA role annotation, `ExternalSecret` (AWS Secrets Manager), KEDA `ScaledObject`
  scaling stream processors on Kafka consumer lag (replaces the CPU HPA).

```bash
kubectl kustomize infrastructure/kubernetes/overlays/dev | kubectl apply -f -      # local cluster
kubectl kustomize infrastructure/kubernetes/overlays/aws | kubectl apply -f -      # after terraform apply
```

## 3. Terraform (AWS)
`infrastructure/terraform/aws`: VPC (3 AZ, public/private/database subnets, NAT per AZ in prod, flow logs), EKS (managed node group, IRSA),
RDS PostgreSQL 16 Multi-AZ + read replica (KMS), ElastiCache Redis (Multi-AZ, TLS, KMS), MSK Kafka (3 brokers, TLS, `min.insync.replicas=2`),
DocumentDB (MongoDB API), S3 telemetry bucket (SSE-KMS, versioning, public-access block, lifecycle rules for warm/cold tiers), Secrets
Manager (generated passwords, JWT secret, device key), IAM roles for the app and External Secrets (least privilege), ingress-nginx NLB,
KEDA, External Secrets, CloudWatch alarms/dashboard + SNS.

```bash
cd infrastructure/terraform/aws
cp terraform.tfvars.example terraform.tfvars   # use the "dev" profile for a cheap demo account
terraform init && terraform apply
$(terraform output -raw kubeconfig_command)
# build & push images to ECR, set image tags in overlays/aws, then:
kubectl kustomize ../../kubernetes/overlays/aws | kubectl apply -f -
```
Terraform was syntactically verified (HCL parse of every file); `terraform validate/plan` were not run locally (binary unavailable) and
are part of CI (`deploy-validation`). Applying it costs real money (MSK, EKS, RDS Multi-AZ are not free-tier) — use the dev profile and `terraform destroy`.

## 4. Cloud portability
Application code only knows generic endpoints. Mapping of managed equivalents:

| capability | config keys | AWS (provided) | GCP | Azure |
|---|---|---|---|---|
| Kafka | `KAFKA_BOOTSTRAP`, `KAFKA_SECURITY_PROTOCOL` | MSK | Managed Service for Apache Kafka / Confluent | Event Hubs (Kafka endpoint) / Confluent |
| Redis | `REDIS_URL` (`rediss://`) | ElastiCache | Memorystore | Azure Cache for Redis |
| PostgreSQL | `DATABASE_URL`… | RDS / Aurora | Cloud SQL / AlloyDB (pgvector) | Flexible Server (pgvector) |
| MongoDB API | `MONGO_URL` | DocumentDB | Atlas / Firestore-Mongo | Cosmos DB for MongoDB |
| Object store | `OBJECT_STORE=s3`, `S3_ENDPOINT`, keys or workload identity | S3 | GCS (interoperability endpoint) | Blob via S3-compatible gateway (e.g. MinIO gateway) |
| Secrets | env from `Secret` | Secrets Manager + External Secrets | Secret Manager + ESO | Key Vault + ESO |
| Identity (OIDC) | `OIDC_JWKS_URL` | Cognito | Identity Platform | Entra ID |
Porting = a new `infrastructure/terraform/<cloud>` directory and an overlay; no application change.

## 5. Secrets & configuration
`.env.example` documents every variable; values are development defaults for synthetic data. Real secrets live only in a secret manager.
`ENV=production` disables `/docs`. TLS terminates at the ingress/ALB; datastore traffic is TLS in the Terraform stack.

## 6. Operations
* Health: `/health/live` (process), `/health/ready` (PostgreSQL required; Redis/Mongo/Kafka failure ⇒ `degraded`, still serving).
* Metrics: `/metrics` on API/edge, ports 9101–9103 on workers; Grafana dashboard `CVI — Pipeline & API overview`; alert rules in
  `infrastructure/observability/alerts.yml` (alert latency SLO, consumer lag, API p95, 5xx rate, breakers, DLQ rate).
* Logs: JSON lines → Promtail → Loki (Grafana Explore); traces: OpenTelemetry (OTLP/HTTP) → Jaeger when `OTLP_ENDPOINT` is set.
* Replay: stop consumers, reset the `stream-processor` group offsets (`kafka-consumer-groups.sh --reset-offsets`), start consumers — safe by idempotency.
* Backups: RDS 14-day PITR, DocumentDB 7-day, S3 versioning; Redis is reconstructible from the stream.
